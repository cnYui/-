# 明日旅途 - 完整系统设计文档

**版本**: v1.0  
**日期**: 2026-03-18  
**状态**: 设计阶段

---

## 一、项目概述

### 1.1 项目定位
"明日旅途"是一款基于 AI 的虚拟旅行社交应用，用户可以通过数字分身进行虚拟旅行，与同城旅行者产生"火花"，收到来自数字分身的旅行日记和邮件。

### 1.2 技术栈
- **前端**: 原生 HTML/CSS/JS + Neo-Brutalism 风格
- **后端**: Node.js + Express + SQLite (better-sqlite3)
- **AI 服务**: DeepSeek (文本生成) + StepFun (图像生成/理解)
- **地图**: 高德地图 JS API

## 二、用户完整流程

### 2.1 流程图

```
└──────┬──────┘
       ↓

│  地图首页   │ ← 可查看地图，但需记忆才能个性化旅行

┌─────────────┐
│ 我的→本地记忆│ ← 添加本地记忆 或 同步 SecondMe 记忆
└──────┬──────┘
       ↓
┌─────────────┐
│ 开始旅行表单 │ ← 输入出发地、目的地、旅行方式
└──────┬──────┘
       ↓
┌─────────────┐
│ AI生成计划  │ ← DeepSeek 结合用户记忆生成定制化计划
└──────┬──────┘
       ↓
┌─────────────┐
│ 旅行计划展示 │ ← 按天数展示卡片 + 雷达图分析
└──────┬──────┘
       ↓
┌─────────────┐
│ 旅途进行中  │ ← 倒计时推进，可发布贴文
└──────┬──────┘
       ↓

│  收信箱     │ ← 每日日记 + 随机事件邮件 + 好友邮件
└─────────────┘
```

### 2.2 详细流程说明

#### 阶段一：强制登录
1. 用户访问任何页面，`auth-check.js` 检查登录状态
2. 未登录则强制跳转到 `login.html`
3. 登录时检查用户名是否已存在（去重逻辑）
4. 登录成功后存储 `user_info` 和 `current_user_id` 到 localStorage

#### 阶段二：添加记忆（可选但推荐）
1. 用户进入"我的"→"本地记忆"
2. 可手动添加记忆，AI 自动分类（个人信息、兴趣爱好、性格特点等）
3. 或连接 SecondMe 同步记忆
4. 记忆将作为 AI 生成旅行计划的上下文

#### 阶段三：开始旅行
1. 用户在地图页面点击"开始旅行"
2. 填写表单：出发地、目的地、旅行方式
3. 后端调用 DeepSeek，结合用户记忆生成定制化旅行计划
4. 返回按天数划分的景点列表，包含坐标信息

#### 阶段四：旅行计划展示
1. 前端以卡片形式展示每日行程
2. 显示雷达图分析（基于记忆分类的匹配度）
3. 右侧显示"建议/不建议"理由

#### 阶段五：旅途进行中
1. 每个景点有倒计时（测试模式 5 秒，正式模式按 duration）
2. 用户可点击"+"发布贴文（文字/图片）
3. 贴文显示在地图上（表情标记）
4. 每天结束自动生成日记

#### 阶段六：城市聊天室
1. 用户发布贴文后，检查同城是否有其他用户
2. 如有，创建临时聊天室
3. AI 生成用户分身对话
4. 提取"火花"时刻保存

#### 阶段七：收信箱
1. **每日日记**: 数字分身发送的旅行日记
2. **随机事件**: 自拍照片、伴手礼等
3. **好友邮件**: 旅途中结交的朋友发来的问候

## 三、核心功能模块

### 3.1 登录模块

**需求**:
- 用户名去重检查
- 强制登录逻辑（无法绕过）
- 登录状态持久化

**API**:
```
POST /api/users
Request: { username, nickname }
Response: { success, data: { id, username, nickname, avatar, bio } }
```

**改进点**:
- 当前 `users.js` 已有去重逻辑，但需要区分"登录"和"注册"
- 需要增加密码字段或使用其他认证方式

### 3.2 记忆模块

**需求**:
- 本地记忆 CRUD
- AI 分类（DeepSeek）
- SecondMe 记忆同步

**分类列表**:
- 个人信息、学业经历、工作经验、技术能力
- 参赛经历、兴趣爱好、性格特点、职业目标

**API**:
```
GET    /api/memories/user/:userId     # 获取用户记忆
POST   /api/memories                  # 创建记忆
POST   /api/memories/batch            # 批量创建
POST   /api/memories/classify         # AI 分类
DELETE /api/memories/:memoryId        # 删除记忆
```

### 3.3 旅行计划模块

**需求**:
- AI 生成定制化旅行计划
- 结合用户记忆作为上下文
- 返回景点坐标用于地图展示
- 雷达图分析

**API**:
```
POST /api/travel/plan/generate   # AI 生成计划
POST /api/travel/plan/start      # 开始旅行
GET  /api/travel/progress/:userId # 获取进度
GET  /api/travel/plans/:userId   # 获取历史计划
```

**雷达图指标**:
基于记忆分类计算匹配度：
- 个人信息匹配度
- 兴趣爱好匹配度
- 性格特点匹配度
- 技术能力相关度
- 职业目标相关度

### 3.4 贴文发布模块

**需求**:
- 支持纯文字发布
- 支持图片发布（拍照/相册）
- 贴文显示在地图上（表情标记）
- 贴文包含地理位置信息

**新增 API**:
```
POST   /api/posts                # 发布贴文
GET    /api/posts/user/:userId   # 获取用户贴文
GET    /api/posts/city/:city     # 获取城市贴文
DELETE /api/posts/:postId        # 删除贴文
```

**新增数据表**:
```sql
CREATE TABLE posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    plan_id INTEGER,
    city TEXT NOT NULL,
    location_name TEXT,
    lat REAL,
    lng REAL,
    content TEXT,
    image_url TEXT,
    mood TEXT,
    mood_detail TEXT,
    is_public INTEGER DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3.5 城市聊天室模块

**需求**:
- 用户发布贴文后触发
- 检测发帖地点周围 1 公里内的历史帖子
- 找到所有发过帖的用户，创建群聊
- 每个用户以分身身份参与（带着记忆）
- 用户打招呼后，AI 分身根据记忆 + 帖子内容回复
- 推荐用户未去过但周围有人去过的地点

**核心逻辑**:
1. **地理匹配**: 使用 Haversine 公式计算距离，筛选 1km 内的帖子
2. **分身对话**: AI 根据用户记忆 + 帖子内容 + 对方消息生成回复
3. **智能推荐**: 分析用户未去过的地点，通过群聊推荐

**API**:
```
POST /api/chatrooms/create-by-location      # 基于地理位置创建聊天室
POST /api/chatrooms/message                 # 用户发送消息
POST /api/chatrooms/generate-responses      # AI 生成分身回复
GET  /api/chatrooms/:chatroomId/members     # 获取聊天室成员
GET  /api/chatrooms/:chatroomId/messages    # 获取聊天记录
GET  /api/chatrooms/unvisited-spots         # 获取未去过的推荐地点
GET  /api/sparks/user/:userId               # 获取火花列表
POST /api/sparks                            # 保存火花
```

**新增数据表**:
```sql
-- 聊天室表
CREATE TABLE chatrooms (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trigger_post_id INTEGER NOT NULL,
    city TEXT NOT NULL,
    district TEXT,
    center_lat REAL NOT NULL,
    center_lng REAL NOT NULL,
    radius INTEGER DEFAULT 1000,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (trigger_post_id) REFERENCES posts(id)
);

-- 聊天室成员表
CREATE TABLE chatroom_members (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    chatroom_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    post_id INTEGER NOT NULL,
    joined_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (chatroom_id) REFERENCES chatrooms(id),
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (post_id) REFERENCES posts(id)
);

-- 聊天消息表
CREATE TABLE chatroom_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    chatroom_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    is_ai_agent INTEGER DEFAULT 1,
    content TEXT NOT NULL,
    message_type TEXT DEFAULT 'text',
    related_post_id INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (chatroom_id) REFERENCES chatrooms(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3.6 收信箱模块

**需求**:
- 每日日记（旅行结束后自动生成）
- 随机事件邮件（自拍、伴手礼等）
- 好友邮件（旅途中结交的朋友）

**邮件类型**:
1. `diary` - 每日日记
2. `selfie` - 自拍照片（AI 生成）
3. `gift` - 伴手礼
4. `friend_greeting` - 好友问候
5. `friend_photo` - 好友合影

**新增 API**:
```
GET  /api/mails/user/:userId     # 获取用户邮件
POST /api/mails                  # 创建邮件
PUT  /api/mails/:mailId/read     # 标记已读
```

**新增数据表**:
```sql
CREATE TABLE mails (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    sender_type TEXT NOT NULL,  -- 'system', 'self', 'friend'
    sender_id INTEGER,          -- 好友ID（如果是好友发送）
    mail_type TEXT NOT NULL,    -- 'diary', 'selfie', 'gift', 'friend_greeting', 'friend_photo'
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    image_url TEXT,
    is_read INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3.7 偶遇与好友模块

**需求**:
- 同一时刻、同一目的地的用户触发偶遇
- 根据性格匹配度计算成为好友的概率
- 好友可能生成合影照片
- 好友会随机发送邮件（问候、祝福等）

**匹配逻辑**:
1. 检查是否有其他用户同时前往相同目的地
2. 计算性格/兴趣匹配度
3. 根据匹配度计算成为好友的概率
4. 成为好友后加入好友列表
5. 好友随机发送邮件

**新增 API**:
```
GET  /api/friends/:userId              # 获取好友列表
POST /api/friends/check-encounter      # 检查偶遇
POST /api/friends/add                  # 添加好友
```
