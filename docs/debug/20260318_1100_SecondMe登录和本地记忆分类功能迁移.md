# SecondMe 登录和本地记忆分类功能迁移

## 📅 迁移时间
2026年3月18日 11:00

## 📦 迁移内容

### 需求概述
将原始项目 `agenTravel` 中的 SecondMe OAuth2 登录认证和本地记忆 AI 分类功能迁移到新项目 `明日旅途`。

### 核心功能
1. **SecondMe OAuth2 登录** - 在"我的"页面连接 SecondMe 账号
2. **SecondMe 记忆同步** - 从 SecondMe 导入用户记忆
3. **本地记忆管理** - 添加、查看、删除本地记忆
4. **AI 智能分类** - 使用 DeepSeek API 自动将用户输入的内容分类成不同标签

---

## 🖥️ 后端实现

### 1. SecondMe OAuth 路由
**文件：** `backend/src/routes/secondme.js`

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/api/secondme/oauth/token` | 用授权码换取 access_token |
| POST | `/api/secondme/oauth/refresh` | 刷新 access_token |
| GET | `/api/secondme/user/info` | 获取 SecondMe 用户信息 |
| GET | `/api/secondme/softmemory` | 获取 SecondMe 软记忆 |

### 2. 记忆管理路由
**文件：** `backend/src/routes/memories.js`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/memories/user/:userId` | 获取用户所有记忆 |
| POST | `/api/memories` | 创建单个记忆 |
| POST | `/api/memories/batch` | 批量创建记忆 |
| PUT | `/api/memories/:memoryId/append` | 追加内容到现有记忆 |
| DELETE | `/api/memories/:memoryId` | 删除记忆 |
| POST | `/api/memories/classify` | AI 分类记忆内容 |

### 3. 路由集成
**文件：** `backend/src/routes/index.js`

```javascript
import secondmeRouter from './secondme.js'
import memoriesRouter from './memories.js'

router.use('/secondme', secondmeRouter)
router.use('/memories', memoriesRouter)
```

## 🔄 SecondMe OAuth 流程

```
用户点击"连接 SecondMe"
    │
    ▼
跳转到 SecondMe 授权页面
    │
    │ 用户授权
    ▼
回调到原页面（带 code 参数）
    │
    ▼
前端检测 URL 参数，调用后端换取 token
    │
    ▼
后端调用 SecondMe API 换取 access_token
    │
    ▼
前端保存 token 到 localStorage
    │
    ▼
获取用户信息并更新页面状态
```

## 🤖 AI 记忆分类流程

```
用户输入个人信息文本
    │
    ▼
调用 /api/memories/classify
    │
    ▼
后端调用 DeepSeek API 分析内容
    │
    ▼
返回分类结果数组：
[
  {"category":"个人信息","title":"基本信息","content":"..."},
  {"category":"兴趣爱好","title":"旅行偏好","content":"..."}
]
    │
    ▼
前端检查是否已存在相同分类
    │
    ├─── 存在 → 追加内容到现有卡片
    │
    └─── 不存在 → 创建新卡片
    │
    ▼
刷新记忆列表显示
```

## ⚠️ 注意事项

1. **SecondMe OAuth**
   - 需要正确配置 redirect_uri
   - 回调页面需要能处理 URL 参数

2. **DeepSeek API**
   - 使用 `deepseek-chat` 模型进行分类
   - temperature 设置为 0.3 以获得稳定输出
   - 需要处理 JSON 解析失败的情况

3. **数据库**
   - 需要 `user_memories` 表存在
   - 表结构：id, user_id, category, title, content, created_at

4. **Token 管理**
   - access_token 存储在 localStorage
   - 自动检测过期并刷新
