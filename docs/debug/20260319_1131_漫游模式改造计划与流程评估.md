# 漫游模式改造计划与流程评估

## 📅 创建时间
2026年3月19日 11:31

## 🎯 目标

将当前“AI 生成旅行计划”模式升级为“真实帖子数据驱动的城市漫游”模式：

1. 使用真实帖子（景点/店铺）作为漫游候选池
2. 用户点击“开始漫游”后，系统生成可推进的日程卡片
3. 推进过程中基于用户记忆 + 帖子内容进行匹配度评估
4. 每日输出推荐总结并发信到收信箱

---

## ✅ 你提出流程的可行性结论

整体方向正确，可落地；但需要补齐以下关键点：

1. **数据分层**：原始数据存储、检索数据、向量数据要分层，不能混在一套表里
2. **在线性能**：地图和漫游计划不能每次都全量扫全城帖子
3. **LLM 调用成本**：每日多景点逐条调用模型会有延迟和成本，需要批处理/缓存策略
4. **推荐可解释性**：向量相似度只是候选召回，最终“推荐/不推荐理由”仍应由结构化规则 + LLM 共同生成

---

## 🧱 推荐架构（按职责拆分）

### 1) 事务数据库（主库）
用于存放结构化业务数据：
- users / user_memories
- raw_posts（原始爬取贴文）
- poi_entities（景点/店铺实体）
- travel_plans / travel_progress
- roam_matches（每步匹配结果）
- mails / travel_diaries

> 生产建议：PostgreSQL + PostGIS（地理检索）

### 2) 对象存储（图片）
- 原图和衍生图放对象存储（MinIO/S3/OSS）
- 主库只存 URL、尺寸、hash、来源

### 3) 向量数据库（召回层）
- 存储帖子语义向量、POI 语义向量、用户记忆向量
- 支持城市过滤 + 类别过滤 + topK 相似检索
- 可选：Qdrant / Milvus / pgvector（若统一在 PG）

### 4) 编排层（服务）
- 漫游计划编排服务（从真实数据生成日程）
- 匹配评估服务（向量召回 + LLM 打分）
- 邮件日记服务（每日总结）

---

## 🔄 目标流程（按你描述整理）

1. 点击“开始漫游”
2. 选择出发地/目的地
3. 系统在目标城市真实帖子池中按策略抽取候选点（吃/逛/玩）
4. 将景点发送大模型生成 Day1~DayN 层级结构（与当前卡片结构兼容）
5. 前端展示漫游卡片并开始推进
6. 每完成一天的旅行计划后：
   - 拉取该点帖子摘要、评论摘要、标签
   - 结合用户记忆做向量相似度检索
   - 触发 LLM 输出匹配 JSON（推荐度、原因、风险提示）
7. 每日结束：发送“当日推荐总结邮件”（当天适合吃/逛的点 + 原因）

## ⚠️ 关键设计问题与建议

### 问题1："将帖子处理成长文章，再拆实体关系"是否必须？
建议：**不是必须一次到位**。

- MVP 阶段先做：帖子清洗 -> 标签化 -> 向量化 -> 召回 + 打分
- 第二阶段再做：实体关系图谱（店铺-菜系-人群偏好-场景）

原因：先保证可跑通，再做复杂知识图谱，风险更低。

### 问题2：向量相似度是否可直接作为“推荐/不推荐”？
建议：**不能单独作为最终结论**。

- 向量相似度适合做“候选召回”
- 最终结论建议由：
  - 结构化信号（标签命中、价格区间、距离、热度）
  - LLM 解释层（推荐理由、不推荐理由）
 共同决定

### 问题3：地图会不会卡？
会，如果继续全量加载。

必须改为：
- 视口查询（按地图可视范围）
- 分页/游标加载
- MarkerCluster 聚合
- 增量更新标记（不要每次清空重建）

### 问题4：模型调用量会不会太大？
会，尤其“每个点都打分”。

建议：
- 每天前置批量预评估（队列异步）
- 前端推进时优先读取缓存评分
- 缺失评分才实时调用模型兜底

## 🧪 分阶段实施（建议顺序）

### Phase 1：数据与检索底座
- 建立真实帖子入库规范
- 处理多图、评论、标签、坐标
- 地图接口改为高性能查询

### Phase 2：漫游计划替换
- “开始漫游”接口上线
- 真实帖子池生成 Day 结构
- 前端卡片直接消费新结构

### Phase 3：向量与匹配评估
- 记忆向量化 + POI 向量化
- 相似召回 + LLM 匹配 JSON
- 当步推荐理由展示

### Phase 4：邮件与体验优化
- 每日总结邮件（适合吃/逛）
- 模型调用缓存与异步队列
- 地图与卡片性能优化收尾

---

## 📌 MVP 建议（先做可跑通版本）

先不引入复杂实体关系图谱，优先实现：

1. 真实帖子入库（含多图）
2. 城市内随机/加权漫游计划
3. 每步匹配 JSON（简单字段）
4. 每日推荐邮件

这样你可以最快看到“真实数据漫游 + 个性化推荐 + 邮件闭环”完整体验。
